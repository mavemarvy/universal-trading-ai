======================================================================

You are the principal architect, quantitative engineer, AI/ML engineer, security engineer, blockchain engineer, backend engineer, frontend engineer, mobile engineer, DevOps engineer, database architect, product designer, QA lead, and trading-systems engineer responsible for building a complete production-grade universal AI trading platform.

2. CORE ARCHITECTURAL PRINCIPLE
======================================================================

The AI must NEVER directly control user money or call an exchange/broker execution API without passing through deterministic policy layers.

Required pipeline:

DATA SOURCES
 -> NORMALIZATION / PROVENANCE
 -> SPECIALIST AI + QUANT BRAINS
 -> MARKET REGIME ENGINE
 -> STRATEGY ENSEMBLE
 -> CONFIDENCE / UNCERTAINTY
 -> TRADE INTENT
 -> PORTFOLIO ENGINE
 -> DETERMINISTIC RISK ENGINE
 -> PLATFORM CAPABILITY CHECK
 -> EXECUTION POLICY
 -> PLATFORM ADAPTER
 -> BROKER / EXCHANGE / DEX
 -> LIVE MONITORING
 -> PROFIT PROTECTION / EXIT
 -> FORENSICS / LEARNING

The AI may recommend actions. Only the deterministic risk/execution stack can approve and send an order.

AI says HOLD + Risk says EXIT = EXIT.
AI says BUY MORE + allocation exhausted = REJECT.
Great opportunity + daily loss limit reached = REJECT.
Profit continues climbing = LET WINNER RUN while protection follows.
Profit materially reverses or the edge invalidates = PARTIAL CLOSE or EXIT according to deterministic and strategy rules.

25. PROFIT TARGET, LET-WINNERS-RUN, AND PROFIT PROTECTION
======================================================================

A user profit target must NOT automatically force an immediate close unless the user chooses that mode.

Default behavior:
- Before target: normal strategy management.
- Target reached: activate Profit Protection Mode.
- Continue monitoring and update peak profit.
- Let winner run while market structure/edge remains healthy.
- Tighten protection progressively as gains increase.
- Exit/trim if profit materially reverses, structure breaks, momentum deteriorates, news risk changes, liquidity disappears, or deterministic trailing rules trigger.

Support:
- peak-profit tracking
- dynamic trailing stop
- ATR/volatility trailing
- market-structure trailing behind swing/support/resistance/liquidity levels
- break-even protection
- partial profit taking
- momentum deterioration
- trend invalidation
- time-based exit
- news protection
- portfolio-level profit floor
- abnormal windfall protection

Example progressive protection concept:
- below target: normal
- target reached: protection activated
- 1x-1.5x target: allow wider continuation
- 1.5x-2x: moderate trail
- 2x-3x: tighter protection
- unusually large gain: aggressively protect windfall

Portfolio-level floor example: target +100, peak session +300, configured maximum giveback 15% -> protected session floor roughly +255, subject to real executable prices and slippage.
